# Guidelines

- For new DOM/browser API usage, use `app.ownerDocument` and `app.ownerWindow` instead of globals; without `app`, derive them from the mounted node's `ownerDocument` and its `defaultView`.

# Linked file assets (excalidraw-app/linkedAssets)

- Feature-gated by `VITE_APP_ENABLE_LINKED_FILES` (string compare against `"true"`); desktop Chrome/Edge only (File System Access API).
- App-layer code lives in `excalidraw-app/linkedAssets/`; the library (`packages/`) must never import from it — the library calls into the app through `packages/excalidraw/linkedAssetsBridge.ts` (`getLinkedAssetsBridge()`, null = feature disabled) and the image-cache resolver injected via `setLinkedImageResolver()` (`packages/element/src/image.ts`).
- Link metadata lives in `element.customData.linkedFile`; sync-frame folder bindings and the manifest live in `frame.customData.syncFolder`. Both survive scene save/load automatically — never store feature data in the linked folder itself.
- Linked images keep only a webp thumbnail (max side 512px) in BinaryFiles; originals are read from disk. Background reconciliation (verifier) must use `CaptureUpdateAction.NEVER` so it never pollutes undo history. `customData.linkedFile.width/height` record the original's dimensions so the render cache can map crop coordinates onto the thumbnail (missing in legacy scenes → falls back to reading the original from disk).
- Duplicating a linked image (copy/paste, duplicate action, alt-drag) clones `customData.linkedFile`; the sync engine detects clones via the manifest (`duplicate.ts`) and gives each clone its own on-disk copy with a sequence suffix (`name-1`, `name-2`…).
- Deleting a linked image on the board only hides it (native `isDeleted`); the file on disk is untouched. Real on-disk deletion happens via the sync frame's context menu "delete hidden images", which first opens a confirmation dialog listing the affected files (`linkedAssets/ui/DeleteHiddenImagesDialog.tsx`, executed by `frameActions.ts` → `deletion.ts`, interactive permission). The frame menu also has "show hidden images" and "reset layout". Deleting the sync frame itself opens a dialog (`linkedAssets/ui/OrphanedFolderDialog.tsx`) asking whether to also remove the folder's images from the board (`deleteFolderImages`); either way the link metadata is stripped (`unlinkFolderLinks`) and files on disk are never touched.
- Folder files unknown to the manifest are auto-imported into the frame in a grid (`importer.ts`); cell size matches the average of existing frame images, falling back to a share of the frame size. The frame grows downward automatically when the grid overflows it (`growFrameToFit`, never shrinks). The "reset layout" frame action reuses the same grid helpers (`gridColumns`/`gridPositionFor`/`fitImageToCell`) with fresh-import sizing, lays images out in manifest order, restores cell-fitted sizes, unhides hidden ones and pulls back images dragged out of the frame.
- Selected linked images get a small link badge inside their top-right corner, rendered on the interactive canvas (`renderLinkedImageBadge` in `packages/excalidraw/renderer/interactiveScene.ts`); a selected sync frame also outlines its linked images dragged outside the frame with a light blue dashed border (`renderLinkedOutOfFrameHighlights`). A single selected linked image shows its bound folder's name in the left properties panel (`packages/excalidraw/components/Actions.tsx`, looks up `customData.syncFolder.rootName`).
- The sync frame context menu also has "refresh from folder" (`actionRefreshSyncFrame` → `verifySyncFrame` in `verifier.ts` — same reconciliation as the background verify, but it may prompt for permission since it's a user gesture). `createSyncFrame` runs `verifyLinkedAssets` right after creating the frame so the folder's images import immediately; a create button also lives in the top-right UI (`renderTopRightUI` in `excalidraw-app/App.tsx`).
- The sidebar tab listing sync frames lives in `linkedAssets/ui/SyncFoldersPanel.tsx`, wired into `excalidraw-app/components/AppSidebar.tsx`; each entry expands to list the folder's synced files.
- New app-layer jotai atoms go in `linkedAssets/state.ts`; jotai is only imported via `excalidraw-app/app-jotai.ts`.
- App-layer file filters (folder scans, imports) must go through the asset-type registry `linkedAssets/assetTypes.ts` (`isImportableAssetFile`) — never hardcode extension lists. Video/PDF handlers are registered as `implemented: false` placeholders; flipping them on requires a real `generatePreview` plus renderer support.

# Rendering performance (Pixi compositor + thumbnail pipeline)

- The static scene has two renderers behind `VITE_APP_ENABLE_PIXI_RENDERER` (see `packages/excalidraw/renderer/pixiRuntime.ts`; also runtime-overridable via `setPixiRendererEnabled`). ON: `packages/excalidraw/renderer/pixiStaticScene.ts` (WebGL sprite compositing). OFF: the original Canvas2D `_renderStaticScene`. Export (PNG/SVG) always uses the Canvas2D/SVG path.
- The Pixi compositor only replaces the final blit: elements are still rendered by the existing Canvas2D/rough.js pipeline into per-element offscreen canvases via `generateElementWithCanvas` (`packages/element/src/renderElement.ts`), then uploaded as textures (`Texture.from(canvas)`). Never bypass the offscreen-canvas generation — that would lose rough.js/text/ink fidelity. Texture/sprite lifecycle is keyed by element id and the `elementWithCanvas` record identity; destroy textures on replacement/removal.
- A canvas can hold only one context type: when the flag is on, `App.tsx` gives `rough.canvas()` a throwaway canvas (never `this.canvas`), and StaticCanvas must skip frames while Pixi init is pending instead of touching the 2d context. Init failure (no WebGL) is the only permanent fallback to Canvas2D.
- Frame clipping uses a Pixi Graphics mask per frame container; arrow label holes use a Graphics with a `cut()` hole; frame outlines are Graphics redrawn per frame (they are never cached into offscreen canvases in the Canvas2D path either).
- The grid is baked once per (gridSize, gridStep, zoom, theme, resolution) into a small tile texture and drawn with a screen-space `TilingSprite` — panning only updates `tilePosition`, never retessellates. Keep it that way: reintroducing per-frame full-screen Graphics grid drawing is a known 5–30ms/frame regression on 4K.
- The Pixi path passes `allowZoomCacheBucketing: true` (and a per-frame `generationBudget`, 8 regenerations) to `generateElementWithCanvas`, so post-gesture canvas regeneration is rate-limited and zoom-bucketed (~12% buckets). The Canvas2D fallback and export paths must stay exact-zoom (no bucketing flag) — export quality depends on it.
- Thumbnail-first rendering: the image cache (`packages/element/src/image.ts`) asks the app-registered `setThumbnailResolver()` before decoding; cache entries carry `sourceScale` (decoded-natural / original-natural), and renderers multiply crop coordinates by `img.naturalWidth / crop.naturalWidth` (`renderElement.ts` image branch). Cropping forces the original first (`startImageCropping` → `updateImageCache({forceOriginal: true})`); `syncImageQuality` in `App.tsx` upgrades visible thumbnail-cached images to originals when zoom makes them larger than the cached tier.
- Tiered thumbnails (256/512/1024 webp) live in a dedicated IDB store (`linkedAssets/thumbnailStore.ts`, keyed by content-hash fileId, LRU cap 3000), generated by a background idle-queue (`enqueueThumbnailGeneration`). SVG/GIF are never thumbnailed.
